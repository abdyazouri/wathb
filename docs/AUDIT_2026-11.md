### ب. بادج "حالة غير معروفة"

يظهر في ٦ أماكن عند عدم تطابق الـ status مع القيم المعرَّفة:

```
BusinessHomeScreen.kt:326 / WageObligationsScreen.kt:262 /
JobApplicationsScreen.kt:245 / AdminVerificationScreen.kt:221,338 /
WorkerAssignmentsScreen.kt:392 / WorkerWagesScreen.kt:332
```

هذا catch-all دفاعي وليس خطأ حرجاً، لكنه يظهر للمستخدم دون أي تلميح عن السبب. **التوصية:** إخفاؤه وتسجيل القيمة غير المعروفة في Logcat.

### ج. أرقام مختلطة (عربي/لاتيني)

- الأرقام في `WorkerHomeScreen` و`JobDetailScreen` مُنسَّقة بالعربية ✅
- الأرقام في `WageObligationsScreen` و`AdminDisputesScreen` بالأرقام اللاتينية (تأتي من السيرفر مباشرةً) ❌

### د. مشكلات أخرى

- **الإشعارات بالـ polling فقط:** لا يوجد FCM/Push — التطبيق يستطلع الـ API يدوياً. الإشعارات تُفاجئ المستخدم فقط عند فتح الشاشة.
- **خريطة بدون بيانات:** `WorkerMapScreen` تعرض الخريطة، لكن pin الوظائف يعتمد على إحداثيات `latitude/longitude` التي قد تكون `null` في بعض الوظائف القديمة.
- **`onNavigate = { _, _ -> }` فارغ:** في `BusinessNotifications` composable بـ `NavGraph.kt:200` — الإشعارات لا تنقل المستخدم للمحتوى ذي الصلة عند الضغط عليها.

## ٦. عوائق النشر على Google Play

### ٦.١ Android

| العائق | الخطورة | التفاصيل |
|--------|---------|---------|
| **لا يوجد توقيع للإصدار** | 🔴 حارج | `build.gradle.kts` لا يحتوي `signingConfigs` لـ release. التطبيق الحالي يستخدم debug signing فقط. يجب إنشاء keystore وتكوينه قبل الرفع |
| **Privacy Policy URL** | 🔴 حارج | Play Store يتطلب رابط سياسة خصوصية مستضافة. `ConsentScreen.kt` يعرض النص لكن لا يوجد URL للـ Store Listing |
| **versionCode = 1** | 🟡 تحذير | مقبول للإصدار الأول، لكن يجب وضع آلية رفعه عند كل إصدار |
| **targetSdk = 35** | ✅ مطابق | يلبي متطلبات Play (API ≥ 33 اعتباراً من 2024) |
| **minSdk = 26** (Android 8.0) | ✅ مقبول | يغطي 97%+ من الأجهزة النشطة |
| **applicationId = "com.wathb.app"** | ✅ | هوية التطبيق صحيحة |
| **إذن الموقع `ACCESS_FINE_LOCATION`** | 🟡 تحذير | Play يتطلب توضيح سبب استخدام الموقع الدقيق في استمارة الـ Store |
| **لا يوجد `app_name` بالعربية في strings.xml** | 🟡 تحذير | اسم التطبيق على الجهاز يظهر كـ "app_name" الافتراضي — تحقق |

### ٦.٢ السيرفر (Render)

| المشكلة | الخطورة | التفاصيل |
|---------|---------|---------|
| **قاعدة البيانات معطَّلة** | 🔴 حارج | فحص `GET /health/` يعيد `DB health-check failed` — أي طلب API حقيقي سيفشل. التطبيق على الجهاز لن يعمل بالكامل حتى تُستعاد الـ DB |
| **متغيرات البيئة على Render** | 🟡 تحذير | `DJANGO_SECRET_KEY`, `DB_*`, `ALLOWED_HOSTS` — تحقق من صحتها بعد استعادة الـ DB |
| **لا يوجد Push Notifications** | 🟠 متوسط | لا FCM — الإشعارات polling فقط. مقبول للتجريب الأولي |
